# Contributing

## Before submitting a change
- Verify loading, success, validation, authorization, timeout, and server-error states.
- Confirm refresh and retry behavior does not duplicate requests or stale data.
- Keep user-facing messages actionable and free of implementation details.

## UI quality checks
- Test keyboard navigation and responsive layout where applicable.
- Keep API assumptions aligned with the backend contract.
- Add or update screenshots and setup notes only when they match the current app.

## Commit checklist
- Run the available tests or build command.
- Record any manual verification steps in the pull request.
- Avoid unrelated formatting-only changes.
